# 일일 기능 규칙

매일 한 번, 웹사이트에서 바로 해볼 수 있는 짧은 콘텐츠를 **딱 1개** 만든다. 같은 기능은 다시 만들지 않는다.

## 절대 규칙 — 메인 페이지 링크 (잊지 말 것)

기능을 만들었으면 **메인 페이지(`index.html`)에서 그 기능으로 가는 링크를 반드시 넣는다.**

- 넣을 곳: 루트 `index.html`의 `<section class="grid" id="experiments">` 안.
- 형태: 기존 카드와 같은 `<a class="card" href="experiments/<slug>/">` (`kicker`, `h2`, `p`, `열기/플레이 →`).
- 홈 카드가 없는 PR은 **미완성이다. 열지 않는다.**
- 페이지 파일만 `experiments/<slug>/`에 두고 홈을 안 고치면 실패로 본다.
- 상단 메뉴에 이름을 넣는 것으로 이 규칙을 대신하지 않는다. 메뉴는 `홈 / 사주 / 게임 / 실험`만 유지하고, 메인에서 쓰는 입구는 **홈 카드**다.

## 이미 있는 것 (다시 만들지 말 것)

- `saju/` — 사주팔자 계산
- `games/` — 그림 짝맞추기
- `experiments/food-worldcup/` — 음식 월드컵
- `experiments/reaction-test/` — 반응속도 테스트
- `experiments/index.html` — 실험 모음 허브 (기능이 아님)

## 고르기 전에 중복 확인 (필수)

체크아웃한 `main`만 보면 열린 PR에 이미 있는 기능을 또 만들게 된다. 아래를 **모두** 본 뒤에만 새 주제를 고른다.

1. `experiments/` 아래 폴더 목록. 이미 있는 slug는 금지.
2. 루트 `index.html`의 `.grid` 카드 제목과 href.
3. `experiments/index.html`의 카드.
4. `gh pr list --state open` — 열린 PR 제목·파일에 같은 주제/slug가 있으면 그 항목은 건너뛴다. 초안 PR도 포함한다.
5. Memories에 적어 둔 이전 slug·한국어 제목.

백로그 맨 위가 이미 위 목록에 있으면 **다음 미완료로 넘어간다.** 반응속도 테스트, 음식 월드컵을 다시 만들지 않는다.

## 한 턴에 할 일

1. 위 중복 확인을 한 뒤, 백로그에서 아직 없는 미완료 1건을 고른다. 비어 있으면 최근 한국 웹 트렌드 또는 개발 유틸로 새 아이디어 1개를 정한다.
2. `experiments/<영문-slug>/index.html`에 완성된 페이지를 만든다. 필요하면 같은 폴더에 CSS/JS를 둔다.
3. **메인 페이지 링크를 반드시 넣는다.** 루트 `index.html`의 `.grid`(id=`experiments`)에 카드를 하나 추가한다. 형식은 기존과 같다 (`kicker`, `h2`, `p`, `열기/플레이 →`). 카드 `href`는 `experiments/<slug>/` 이다. 이 카드가 없으면 방문자가 홈에서 새 기능을 열 수 없다.
4. `experiments/index.html`에도 같은 카드를 추가한다. `href`는 `<slug>/` 이다.
5. **상단 메뉴는 늘리지 않는다.** 모든 페이지 `.nav`는 `홈 / 사주 / 게임 / 실험` 네 칸만 둔다. 홈에만 그 뒤에 `방명록`을 둔다. 새 기능 이름을 상단 메뉴에 하나씩 추가하지 않는다. 실험 페이지의 `.nav`에서 `실험`은 `../` 이고 `aria-current="page"`를 붙인다.
6. 실험 카드가 많아져 허브가 지저분하면 `experiments/index.html`을 **놀이 / 도구**처럼 소제목으로 나눠 정리한다. 상단 메뉴는 그대로 둔다.
7. 이 규칙의 「이미 있는 것」과 백로그를 갱신한다 (완료 표시 + 다음 후보 1~2개). Memories에도 slug와 한국어 제목을 적는다.
8. PR을 열기 전에 확인한다. 루트 `index.html`에 새 카드가 있고, 그 `href`를 브라우저에서 열면 방금 만든 페이지가 나온다. 홈 카드가 없으면 PR을 열지 말고 카드를 먼저 넣는다. 확인이 끝나면 **PR을 연다.** main에 직접 푸시하지 않는다.

## 메뉴 상대 경로

| 파일 | 홈 | 사주 | 게임 | 실험 |
|------|----|------|------|------|
| `index.html` | `./` | `saju/` | `games/` | `experiments/` |
| `saju/`, `games/` | `../` | `../saju/` 또는 `./` | `../games/` 또는 `./` | `../experiments/` |
| `experiments/index.html` | `../` | `../saju/` | `../games/` | `./` |
| `experiments/<slug>/` | `../../` | `../../saju/` | `../../games/` | `../` |

## 반드시 지킬 것

- HTML/CSS/JS만. 서버, 로그인, 결제, 외부 API 키 없음.
- 방문자의 브라우저에서만 동작. 입력값은 서버로 보내지 않음. 기록은 localStorage만.
- 기존 사주/그림 짝맞추기/음식 월드컵/반응속도를 깨지 않음.
- 안내 문구는 한국어. 개발 유틸은 입력란에 코드·영문이 들어가도 된다.
- 한 기능 용량은 작게 (큰 영상·이미지 넣지 않음).
- 기존 `css/site.css` 톤(먹색, 주홍, Gowun Batang)을 맞춘다.
- 저작권 있는 브랜드/캐릭터/가수는 쓰지 않음.
- 하루 1개. 미완성으로 끝내지 않음.
- **메인(`index.html`) `.grid`에 새 기능 카드를 반드시 넣는다.** 홈 링크 없는 기능은 만들지 않은 것과 같다.
- 실험 허브(`experiments/index.html`)에도 같은 카드를 넣는다.
- 상단 메뉴에 개별 기능 이름을 추가하지 않는다.
- 이미 폴더·홈 카드·열린 PR·Memories에 있는 주제는 다시 만들지 않는다.

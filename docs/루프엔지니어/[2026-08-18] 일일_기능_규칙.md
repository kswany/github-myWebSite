# 일일 기능 규칙

매일 한 번, 웹사이트에서 바로 해볼 수 있는 짧은 콘텐츠를 **딱 1개** 만든다. 같은 기능은 다시 만들지 않는다. 자동화가 꼬여도 **기존 사이트를 고치려 하지 말고 멈춘다.**

## PR 열기 전 필수 체크리스트 (하나라도 빠지면 실패)

새 기능을 만들었으면 **아래 네 가지를 반드시** 한다. 홈 카드만 넣고 메뉴를 빼면 방문자가 주소를 몰라 접속할 수 없다.

1. **홈 카드** — 루트 `index.html` `.grid`에 `<a class="card" href="experiments/<slug>/">`
2. **상단 메뉴** — `js/nav.js`의 `EXPERIMENTS` 배열에 `{ slug: "<slug>", label: "<한글 이름>" }` **한 줄 추가**
3. **실험 허브** — `experiments/index.html`에 같은 카드 추가
4. **페이지 스크립트** — 새 `experiments/<slug>/index.html` `<body>` 끝에 `nav.js` + `lab.js` 로드

PR 전에 **홈·사주·게임·방명록 아무 페이지에서나** 상단 메뉴에 새 기능 이름이 보이고, 클릭하면 페이지가 열려야 한다. 메뉴에 없으면 **PR을 열지 않는다.**

## 절대 규칙 — 기존 파일을 깨지 말 것

이 턴에서 **새로 만드거나 고쳐도 되는 것**만 손댄다.

허용:
- `experiments/<새-slug>/` 안의 새 파일만
- 루트 `index.html`의 `.grid`에 카드 **한 줄 추가**
- `experiments/index.html`에 같은 카드 **한 줄 추가**
- `js/nav.js`의 `EXPERIMENTS`에 항목 **한 줄 추가** (전 페이지 서브 메뉴)
- 모든 HTML에 `nav.js` `<script>`가 없으면 **한 줄 추가**
- 이 문서의 「이미 있는 것」과 백로그 갱신

금지 (열지도 말고 덮어쓰지도 말 것):
- `css/site.css`, `js/lab.js`
- `saju/`, `games/`, `guestbook/`
- 이미 있는 `experiments/food-worldcup/`, `experiments/reaction-test/` 등 기존 slug 폴더
- 홈 히어로·메뉴·방명록 구조 리팩터
- 실패했다고 두 번째 기능을 만들거나 사이트 전체를 “고치기”

톤은 `css/site.css`를 **읽어서 맞추고**, 페이지 전용 스타일은 `experiments/<새-slug>/` 안에만 둔다. `site.css`를 수정해서 맞추지 않는다.

**main에 직접 푸시하지 않는다. PR만 연다.** 한 턴에 PR 하나, 기능 하나.

## 절대 규칙 — 메인 페이지 링크 (잊지 말 것)

기능을 만들었으면 **메인 페이지(`index.html`)에서 그 기능으로 가는 링크를 반드시 넣는다.**

- 넣을 곳: 루트 `index.html`의 `<section class="grid" id="experiments">` 안.
- 형태: 기존 카드와 같은 `<a class="card" href="experiments/<slug>/" data-tone="…">` (`kicker`, `h2`, 짧은 `p`). 가능하면 `.card-visual`에 Lucide 스타일 SVG.
- 홈 카드가 없는 PR은 **미완성이다. 열지 않는다.**
- 페이지 파일만 `experiments/<slug>/`에 두고 홈을 안 고치면 실패로 본다.
- 상단 메뉴에 이름을 넣는 것으로 홈 카드 규칙을 대신하지 않는다. 기본 메뉴는 `홈 / 사주 / 게임 / 실험 / 방명록`이고, 개별 실험은 **`js/nav.js`가 같은 `.nav`에 붙인다.**

## 이미 있는 것 (다시 만들지 말 것)

- `saju/` — 사주팔자 계산
- `games/` — 그림 짝맞추기
- `experiments/food-worldcup/` — 음식 월드컵
- `experiments/reaction-test/` — 반응속도 테스트
- `experiments/balance-game/` — 밸런스 게임
- `experiments/index.html` — 실험 모음 허브 (기능이 아님)
- `guestbook/` — 방명록·방문 기록 페이지 (기능이 아님)

## 고르기 전에 중복 확인 (필수)

체크아웃한 `main`만 보면 열린 PR에 이미 있는 기능을 또 만들게 된다. 아래를 **모두** 본 뒤에만 새 주제를 고른다.

1. `experiments/` 아래 폴더 목록. 이미 있는 slug는 금지.
2. 루트 `index.html`의 `.grid` 카드 제목과 href.
3. `experiments/index.html`의 카드.
4. `gh pr list --state open` — 열린 PR 제목·파일에 같은 주제/slug가 있으면 그 항목은 건너뛴다. 초안 PR도 포함한다.
5. Memories에 적어 둔 이전 slug·한국어 제목.

백로그 맨 위가 이미 위 목록에 있으면 **다음 미완료로 넘어간다.** 반응속도 테스트, 음식 월드컵을 다시 만들지 않는다.

## 한 턴에 할 일

1. 위 중복 확인을 한 뒤, 백로그에서 아직 없는 미완료 1건을 고른다. 비어 있으면 최근 한국 웹 트렌드 또는 개발 유틸로 새 아이디어 1개를 정한다.
2. `experiments/<영문-slug>/index.html`에 완성된 페이지를 만든다. 필요하면 같은 폴더에 CSS/JS를 둔다.
3. **메인 페이지 링크를 반드시 넣는다.** 루트 `index.html`의 `.grid`(id=`experiments`)에 카드를 하나 추가한다. 형식은 기존과 같다 (`data-tone`, `kicker`, `h2`, 짧은 `p`). 카드 `href`는 `experiments/<slug>/` 이다. 이 카드가 없으면 방문자가 홈에서 새 기능을 열 수 없다.
4. `experiments/index.html`에도 같은 카드를 추가한다. `href`는 `<slug>/` 이다.
5. **상단 메뉴에 실험 바로가기를 붙인다.** `js/nav.js`의 `EXPERIMENTS` 배열에 `{ slug, label }`을 추가하고, 새 페이지 `<body>` 끝에 `nav.js`를 `lab.js`와 같이 넣는다. 모든 HTML(홈·사주·게임·방명록·실험 허브·각 slug)에서 서브 메뉴가 보여야 한다. 홈 카드만 있고 메뉴에 없으면 확인이 어렵다.
6. **상단 기본 메뉴 다섯 칸은 그대로 둔다.** `홈 / 사주 / 게임 / 실험 / 방명록`만 유지하고, 개별 기능 이름은 `js/nav.js`가 같은 `.nav` 끝에 붙인다. 얇은 테두리 서브 줄을 만들지 않는다.
7. 실험 카드가 많아져 허브가 지저분하면 `experiments/index.html`을 **놀이 / 도구**처럼 소제목으로 나눠 정리한다.
8. 이 규칙의 「이미 있는 것」과 백로그를 갱신한다 (완료 표시 + 다음 후보 1~2개). Memories에도 slug와 한국어 제목을 적는다.
9. PR을 열기 전에 확인한다. 루트 `index.html`에 새 카드가 있고, **어느 페이지에서든** 서브 메뉴를 누르면 방금 만든 페이지가 나온다. 홈 카드·메뉴 링크가 없으면 PR을 열지 말고 먼저 넣는다. 확인이 끝나면 **PR을 연다.** main에 직접 푸시하지 않는다.

## 반드시 지킬 것

- HTML/CSS/JS만. 서버, 로그인, 결제, 외부 API 키 없음.
- 방문자의 브라우저에서만 동작. 입력값은 서버로 보내지 않음. 기록은 localStorage만.
- 기존 사주/그림 짝맞추기/음식 월드컵/반응속도를 깨지 않음. 그 폴더와 `css/site.css`는 수정하지 않음.
- 안내 문구는 한국어. 개발 유틸은 입력란에 코드·영문이 들어가도 된다.
- 한 기능 용량은 작게 (큰 영상·이미지 넣지 않음).
- 기존 `css/site.css` 톤을 **읽어서** 맞춘다. 배경은 오프화이트 `#F9FAFB`, 카드는 흰 면·큰 둥근 모서리·은은한 그림자, 제목은 Pretendard ExtraBold. `site.css`를 고쳐서 맞추지 않는다.
- 저작권 있는 브랜드/캐릭터/가수는 쓰지 않음.
- 하루 1개. 미완성으로 끝내지 않음. 실패하면 재시도·두 번째 주제로 넘어가지 말고 PR 없이 멈춘다.
- **메인(`index.html`) `.grid`에 새 기능 카드를 반드시 넣는다.** 홈 링크 없는 기능은 만들지 않은 것과 같다.
- 실험 허브(`experiments/index.html`)에도 같은 카드를 넣는다.
- 상단 기본 메뉴(`홈 / 사주 / 게임 / 실험 / 방명록`)는 다섯 칸만 유지한다.
- **새 실험은 `js/nav.js`의 `EXPERIMENTS`에 slug·label을 추가**하고, 모든 HTML에 `nav.js`를 넣어 상단 `.nav`에 바로가기를 붙인다. 홈 카드만으로는 부족하다.
- 이미 폴더·홈 카드·열린 PR·Memories에 있는 주제는 다시 만들지 않는다.

## 한국판 neal.fun (만들 때 지킬 결)

목표는 [neal.fun](https://neal.fun/)을 **베끼는 것이 아니라**, 영어를 잘 못 읽는 사람도 바로 만질 수 있는 **한국어 버전**을 만드는 것이다. 이름·그림·규칙을 복사하지 말고, 같은 기분만 가져온다.

가져올 것:
- 홈은 오프화이트 배경 + 떠오르는 카드 그리드. 긴 설명·큰 통계 패널은 두지 않는다
- 설명보다 바로 클릭·드래그·입력. 문구는 짧은 한국어
- 한 가지 질문만 (완벽한 원을 그릴 수 있나, 돈이 얼마나 큰가)
- 숫자는 표 대신 깜빡임·스크롤·게이지로
- 접속 건수는 홈 아래 `오늘 n · 전체 n` 한 줄만. 방명록·방문 기록은 `guestbook/` 페이지
- 작을수록 좋다

가져오지 말 것:
- Infinite Craft처럼 서버 LLM·무한 조합 DB
- Sandboxels처럼 수백 개 입자 물리
- Internet Roadtrip처럼 외부 지도 API
- Password Game 전체 복제
- 저작권 있는 로고·CAPTCHA 상표
- 홈을 다시 어두운 테마나 큰 방명록 보드로 되돌리는 것

매일 한 턴에 맞는 오마주 예: 원 그리기 점수, 가상 돈 쓰기, 하루가 어디로 갔는지, 출생/인구를 점으로 보여 주기, 크기 비교 스크롤. 이런 것은 정적 HTML/JS로 하루 분량이다.
